# Renderer execution rules

This is a short operating reference, not an implementation queue. The user's
current request and AGENTS.md govern scope. Read the Renderer/Lab guides and
relevant catalog category; use [architecture](renderer_architecture.md) for design,
[roadmap](retained_renderer_plan.md) for status and [validation](benchmark_workflow.md)
for evidence. Consult deeper findings only when relevant.

- Inspect current owners and worktree before changing them. Preserve concurrent
  work, tested controls, staged artifacts, ignored assets and visual references.
- Implement connected responsibilities through existing owners; replace obsolete
  routes. No new engine framework or permanently parallel renderer.
- Identify the work a change should eliminate and validate at meaningful design,
  working-path and complete-comparison checkpoints. Individual intermediate edits
  need not each improve performance. Resolve uncertainty with a bounded diagnostic
  that can change an implementation decision, not another optimization campaign.
- Report completed capability, measured effect and remaining integration gaps
  separately. Fewer draws, smaller uploads, cache hits or shorter caller waits are
  not an overall speedup. If a complete path regresses, identify the dominant cost
  and make a focused correction; preserve the result and its limits honestly.
- Keep tests for behavior and ownership. Retire assertions of superseded internals
  only with equivalent behavioral coverage. Never weaken correctness for timing.
- Routine authorized implementation/build/test work needs no repeated permission.
  Preserve applicable visual, patch-table, staging, install and launch rules;
  explicit user authorization persists and takes precedence over local guidance.
- No automatic baseline campaign on continuation. No injected compile for docs or
  standalone tooling edits; changes to C3X.h/injected_code.c use the approved
  `TEST_INJECTED_CODE_COMPILE.bat`. Do not launch Civ III without authorization.

Keep current status updated in place. Each implementation handoff identifies the
responsibility completed, work eliminated, production path replaced, measured
whole-workload effect and next unfinished responsibility. Put detailed evidence
in receipts; avoid competing “next steps” throughout the docs. Preserve the agreed
ownership model while changing mechanisms when evidence warrants it. Honor new
user requests to pause; the earlier documentation/reconvene pause is released.
