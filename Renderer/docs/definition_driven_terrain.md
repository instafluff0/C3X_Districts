# Definition-Driven Native Terrain

> Historical note: this document records the M6.3-M6.5 bootstrap. I11
> supersedes its native-underlay fallback policy: custom-on production now owns
> the complete `m19` plane and fails visibly without native replay.

M6.3 replaces the hard-coded grassland bootstrap with a native layered-definition reader. The injected bridge supplies `Renderer/default.custom_rendering.txt`, an optional scenario `scenario.custom_rendering.txt` resolved through Civ III's asset search, and an optional `Renderer/custom.custom_rendering.txt`. The DLL merges complete `#Pack`, `#Asset`, and terrain `#Rule` sections in `default -> scenario -> custom` order. A later `disabled = true` section removes the inherited definition; priority and layer/order select the winning terrain rule.

The runtime receives only generic pack roots and logical asset IDs. It validates bounded `c3x.asset_pack.v0`, `c3x.normalized_mesh.v0`, and `c3x.material.v0` records, then creates one BC3 shader resource per supported Civ III terrain type. The shader chooses the resource selected by the winning definition and uses map-coordinate UVs so adjacent same-material tiles sample one continuous texture field rather than stretching an entire source texture independently over every diamond.

The local compiler currently emits six complete flat-surface material families: desert, plains, grassland, tundra, coast, and sea. These are the families whose bounded base-color payload and flat replacement dependencies are proven. Flood plains, hills, mountains, forest, jungle, marsh, volcano, ocean, polar ice, and landmarks remain explicit Civ III fallbacks because their feature/relief/edge geometry or material selection is incomplete. Default rules may name a future logical asset for these families, but the missing pack entry remains transparent and the native tile below is preserved. No procedural color is used as fallback or counted as real-art coverage.

The six mapped families are material-only bootstrap assets, not finished Civ VI terrain. M6.5 removes coordinate-seeded per-tile brightness blocks and uses the four valid staggered-map neighbors to mix different mapped materials through a symmetric edge band. Where the neighboring family is an explicit fallback, that band fades to transparent over Civ III's native terrain rather than ending at a hard custom diamond. This is an interim continuity pass; authored transitions, relief geometry, water surfaces, clutter, and feature meshes remain M6.6 work.

When any visible tile falls back, the bridge replays Civ III's complete staggered base-terrain underlay before compositing accepted custom terrain. This is necessary because Civ III's native base coverage calls are companion records rather than one-to-one calls for the renderer's logical tiles; attempting to replay only the returned logical fallback index left black wedges under hills and other retained relief sprites. Accepted custom interiors remain opaque, mapped/mapped edges mix both normalized materials, and mapped/fallback edges expose the native base through partial alpha.

`Renderer/terrain/m6_3_runtime_coverage.json` is the tracked ownership ledger. The ignored local `Renderer/packs/TerrainNormalized` directory contains converted texture payloads and never becomes redistributable C3X content. Source identities, package formats, installed paths, and provenance remain in the offline build report rather than the runtime pack.

The portable smoke builds synthetic default/scenario/custom layers, renders three distinct material slots, applies one custom rule override, and proves that a corrupt fourth dependency falls back alone. Its M6.5 fixture then samples two adjacent mapped materials at both interiors and their shared edge, replaces one side with a fallback family, and requires a partial-alpha transition to the native underlay. The local gate rebuilds the six-family pack from installed assets and renders desert, plains, grassland, and tundra through the same native definition entry point. Existing Civ III fog, features, roads, rivers, resources, cities, units, borders, labels, selection, minimap, HUD, and UI remain outside current terrain ownership.
